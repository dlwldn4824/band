## 2. 제출할 때 넣어야 하는 값

### 2-1. 심사용 계정 (둘 다 필수)

카카오 로그인만으로는 미국 심사자가 못 들어옵니다. **이메일 로그인으로 들어오라고 적어 주세요.**

App Store Connect > 앱 심사 정보 > 로그인 정보, Play Console > 앱 액세스 권한 에 아래를 그대로 씁니다.

```
로그인 없이도 대부분의 화면을 볼 수 있습니다. 「로그인 없이 둘러보기」를 누르세요.

계정이 필요한 화면은 이메일로 들어오시면 됩니다.
1. 시작 화면 > 「이메일로 시작하기」
2. 아무 이메일 주소나 넣고 「인증 코드 받기」
3. 화면에 6자리 코드가 바로 표시됩니다. 그 코드를 넣으세요.

(메일 발송 서버는 아직 연결 전이라 코드를 화면에 표시합니다.)

카카오 로그인은 한국 계정이 필요해서 심사에는 쓰지 마세요.
```

⚠︎ 이 안내는 **메일 발송 서버가 붙기 전까지만** 맞습니다. 서버가 붙으면 코드가 화면에 안 뜨므로, 그때는 진짜 테스트 계정을 하나 만들어 아이디·비밀번호를 적어야 합니다.

### 2-2. QR 입장 재현 방법

심사자는 공연장에 못 옵니다. 심사 노트에 적으세요.

```
QR 입장은 두 화면으로 확인할 수 있습니다.
· 관객 쪽 티켓: 내 티켓 > 아무 티켓이나 열기 (QR 이 보입니다)
· 운영진 쪽 스캔: 마이 > 공연 관리 > 입장 관리
실제 스캔은 카메라가 필요하므로, 필요하시면 영상을 보내 드리겠습니다.
```

### 2-3. 권한 설명 문구

네이티브로 감쌀 때 그대로 넣으세요. "앱 기능을 위해" 같은 문구는 반려 사유입니다.

**iOS — `Info.plist`**

```xml
<key>NSCameraUsageDescription</key>
<string>공연 입구에서 티켓 QR 코드를 확인하기 위해 카메라를 사용합니다.</string>

<key>NSLocationWhenInUseUsageDescription</key>
<string>내 주변에서 열리는 공연을 가까운 순서로 보여 주기 위해 위치를 사용합니다. 위치는 저장하지 않습니다.</string>

<key>NSPhotoLibraryAddUsageDescription</key>
<string>만든 초대 티켓 이미지를 사진에 저장하기 위해 사용합니다.</string>
```

**Android — `AndroidManifest.xml`**

```xml
<uses-permission android:name="android.permission.CAMERA" />
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
<uses-permission android:name="android.permission.POST_NOTIFICATIONS" />
<uses-permission android:name="android.permission.INTERNET" />
```

⚠︎ 빌드한 뒤 `app/build/outputs/.../AndroidManifest.xml` 을 직접 열어 보세요. Capacitor 플러그인이 **쓰지도 않는 권한을 끌고 오는 일이 흔하고, 그것만으로 걸립니다.**
`POST_NOTIFICATIONS` 는 선언만으로는 안 되고 실행 중에 요청해야 알림이 갑니다.

### 2-4. 개인정보 라벨 · 데이터 안전

양쪽 설문에 같은 목록을 씁니다. 근거는 `/ui/legal/privacy` 입니다.

| 모으는 것 | 쓰는 데 | 계정에 연결되나 | 추적에 쓰나 |
|---|---|---|---|
| 이메일 주소 | 계정 | 예 | 아니오 |
| 이름 · 닉네임 | 계정, 예매자 확인 | 예 | 아니오 |
| 전화번호 | 예매 연락 | 예 | 아니오 |
| 대략적 위치 | 가까운 공연 정렬 | 아니오 | 아니오 |
| 이용자가 쓴 글 (채팅 · 방명록) | 서비스 기능 | 예 | 아니오 |
| 기기 ID · 푸시 토큰 | 알림 발송 | 예 | 아니오 |
| 진단 · 오류 기록 | 장애 대응 | 아니오 | 아니오 |

⚠︎ **Firebase SDK 가 자동으로 모으는 것(기기 ID, 크래시 로그)까지 넣어야 합니다.** 여기서 빠뜨려서 내려가는 경우가 많습니다.
제3자 전달처: Google(Firebase, 미국), Vercel, 카카오, 결제대행사(결제를 켠 뒤).

### 2-5. 구글이 따로 요구하는 것

- **계정 삭제 웹 주소** — 앱을 깔지 않고도 삭제를 요청할 수 있는 페이지가 따로 있어야 합니다. 앱 안의 삭제 버튼만으로는 부족합니다. ⚠︎ 아직 없습니다 — 랜딩에 한 장 만들어야 합니다.
- **개인정보처리방침 URL** — 스토어 등록 정보에 넣을 **웹 주소**가 필요합니다. 지금 약관은 앱 안(`/ui/legal/privacy`)에만 있습니다. 같은 내용을 웹에서도 열리게 해야 합니다.

### 2-6. 일정

구글은 **2023년 11월 13일 이후에 만든 개인 계정**이면 프로덕션 전에 **테스터 12명이 14일 연속** 비공개 테스트에 있어야 합니다. 심사 2~3일이 아니라 **2주를 먼저 잡으세요.** 동아리 사람 12명을 미리 모아 두면 됩니다.

## 3. 아직 안 끝난 것

### 3-1. 목업 데이터 (제일 큼)

`/ui` 화면 대부분이 `src/mocks/bandyLight.ts` 를 봅니다. 멜로딕 단독 공연, 이지우, 34,000원이 그대로 보입니다. **이건 코드를 고쳐서 막을 수 있는 게 아니라 진짜 데이터가 들어와야 하는 문제입니다.**

둘 중 하나입니다.
- 실제 공연 하나를 넣고 그 데이터로 심사를 받는다 (권장 — 이미 공연을 3회 치렀습니다)
- 데이터가 없을 때의 빈 화면을 전부 만들고, 비어 있는 상태로 심사를 받는다

지금은 **빈 화면이 아니라 가짜 데이터가 채워져 있어서 더 위험합니다.**

### 3-2. 서버가 있어야 끝나는 것

| 무엇 | 지금 | 왜 서버가 필요한가 |
|---|---|---|
| 신고 접수 | 기기에만 쌓임 | 운영자에게 닿지 않으면 약관의 「24시간 안에 조치」가 거짓말이 됩니다 |
| 차단 | 기기에만 저장 | 기기를 바꾸면 차단이 풀립니다 |
| 계정 삭제 | 기기에서만 지움 | 서버 데이터가 그대로 남습니다 |
| 이메일 코드 | 브라우저가 만들고 확인 | 지금 구조로는 아무나 들어올 수 있습니다 |
| 결제 확정 | 없음 | 브라우저 성공값만 믿으면 공짜 티켓이 만들어집니다 |

**심사는 통과할 수 있지만, 통과한 뒤에 이게 진짜 문제가 됩니다.** 특히 계정 삭제와 결제 확정.

### 3-3. 휴대폰 맞대기

⚠︎ 아이폰끼리 NFC 로 주고받는 길이 없습니다. QR 로 바꾸는 쪽을 권합니다 — [스토어-심사-반려-예상.md §1-5](./스토어-심사-반려-예상.md).

### 3-4. 사업자 정보

`src/lightui/legal/content.ts` 의 `BIZ` 가 비어 있습니다. 사업자등록을 내면 거기만 채우면 약관 화면에 바로 뜹니다. 그 전까지는 "준비 중" 으로 표시되고, **앱에서 직접 돈을 받으면 안 됩니다.**

## 4. 약관은 초안입니다

`src/lightui/legal/content.ts` 의 세 문서는 변호사 검토를 받지 않았습니다. 읽을 수 있게는 써 뒀지만, 실제로 돈을 받기 시작하기 전에 한 번 봐 달라고 하세요. 특히 환불 비율(8일 전 전액 / 7~3일 전 90% / 2일~전날 70% / 당일 불가)은 **저희가 정한 값이지 법에서 정한 값이 아닙니다.**
